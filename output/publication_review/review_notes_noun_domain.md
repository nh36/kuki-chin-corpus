# Why there is no dictionary slice

There is no dictionary slice because this packet is grammar-facing rather than lexical. It should not create dictionary entries for `gam`, `aksi`, `minam`, `thugen`, `Abraham`, `Topa`, or other noun strings.

That restraint matters because compounds, opaque lexicalized forms, proper nouns, nominalization-boundary nouns, NP/possession material, and dictionary or chrestomathy routing all remain unsettled. The current packet works because it establishes a grammar-facing noun-domain foundation rather than exporting a lexical-headword layer too early.

# What does not yet work

This packet does not provide a full noun chapter. It does not provide a full compound-noun chapter. It does not provide a full proper-noun chapter. It does not provide a full noun inflection chapter. It does not provide a dictionary slice. It does not provide a full chrestomathy/dictionary routing account.

It also does not yet settle transparent-compound selection, opaque-compound treatment, proper-name routing, nominalization-boundary noun treatment, or the editorial split between grammar-facing noun-domain prose and later lexical export. That restraint is useful. The packet works because it keeps the first claim smaller than the unresolved noun-domain architecture around it.

The packet’s deferred and boundary-only rows are now explicit.

- `minam` and `thugen` remain outside the first core slice because transparent compounds require a later compound-focused sub-scope.
- `singnai` and `lamethuai` remain outside the first core slice because they are still compound-transparency problem rows rather than safe first-slice anchors.
- `sanggam` remains outside the first core slice because it is opaque or lexicalized rather than a safe transparent-compound example.
- `kholhna` remains outside the first core slice because it is nominalization-boundary material rather than a clean simple noun stem.
- `Abraham` remains outside the first core slice because proper nouns are more lexical-inventory-like than the simple noun anchors.
- `Topa` remains outside the first core slice because it is title-like and boundary-heavy.
- `Topa' inn` and broader possessor syntax remain outside the first core slice because they belong with NP structure / possession rather than the noun-domain packet.
- pronoun-led possessors and person-head material remain outside the first core slice because they overlap with pronouns and NP structure.
- relator/postposition or case-dominated noun rows remain outside the first core slice because their main value belongs with the relator/postposition and case-marking packets.
- analyzer-noisy, report-only, or count-only noun-domain claims remain outside the first core slice because attestation alone does not make a row safe for the first print-facing claim.
- any broad noun chapter, compound chapter, proper-noun chapter, or dictionary/chrestomathy routing claim remains outside the first core slice because the current packet is only a narrow simple-noun-stem slice.

These deferrals are also why the packet should stop here. It is better to hand off a narrow stable noun-domain slice than to force unsettled compound, proper-noun, or lexical-routing questions into premature print prose.
