# 1. Literature statement

The controlling sources agree that `hong-` and `kong-` cannot be reduced to one simple label.

1. `docs/grammar/morphemes/01-prefixes.md` treats `hong-` as venitive or toward-speaker/deictic, but also records Otsuka-style inverse-like use when a `-sak` causee/beneficiary is first/second person.
2. The agreement/pronoun report layer (`docs/grammar/reports/05-verb-03-agreement.md`, `docs/grammar/reports/06-func-01-pronouns.md`) keeps a participant-oriented contrast (`hong-` inverse-like side, `kong-` direct-like side), but report-level default glossing sometimes flattens context-sensitive rows.
3. The analyzer-gap literature files (`docs/grammar/ANALYZER_LITERATURE_GAPS.md`, `docs/grammar/ANALYZER_GAPS_CORPUS_EXAMPLES.md`, `docs/grammar/ANALYZER_GAPS_QUICK_REFERENCE.md`) preserve the strongest explicit constraint: in Otsuka-style causative/benefactive environments, `hong-` is obligatory with first/second-person causee/beneficiary.
4. Bible-corpus rows and elicited/literature rows must be separated: Bible rows anchor first-slice grammar prose; elicited Otsuka rows remain blocked but diagnostically important for constraint tracking.
5. Therefore, not every `hong` token is object-prefixal/inverse-like; many are better analyzed as deictic/venitive or constructional discourse material.

# 3. Focused diagnosis of Matthew 25:37

`Topa aw, cikin na gilkial hong mu-in an hong pia ka hi uh hiam?` is quoted speech where the speaker group is first-person plural and the addressee is second person singular (`Topa`, `na`).

The clause-level participant configuration is clearly **1PL → 2SG** (“when did we see you hungry and give you food?”). However, this does **not** force a clean object-prefix reading for `hong` in this verse. Two facts matter:

1. both `hong` tokens occur in the same quoted clause (`hong mu-in`, `hong pia`);
2. the row has long been mixed in the literature/report layer between inverse-like and deictic/participant-oriented analyses.

Decision: in Matthew 25:37, both `hong` tokens are glossed consistently as **`SAP.ORIENT`** (participant/deictic orientation toward the speech-act participant), not as a clean arrow diagnostic. The row remains **supporting, not diagnostic**.

# 4. Focused diagnosis of Matthew 4:9

Matthew 4:9 remains the strongest paired Gospel diagnostic:

- `kei hong bia` is best analyzed as inverse-like **`2→1`** in this clause (worship directed to first-person `kei`);
- `nangma tungah kong pia` is best analyzed as direct-like **`1→2`**;
- explicit pronouns (`kei`, `nangma`) and the paired `hong`/`kong` contrast in one sentence make this row unusually clear.

Decision: keep `hongbia` and `kongpia` promoted as the cleanest paired diagnostic in the first slice.

# 5. Focused diagnosis of Genesis 41:41

Genesis 41:41 (`nang kong koih`) is a strong kong-side diagnostic. The controller is first person and the target is explicit second person (`nang`), with no major deictic-motion confound.

Decision: keep `kongkoih` promoted as a core direct-like **`1→2`** OT anchor.

# 6. Diagnostic conclusion

1. **True diagnostics (core promoted rows):** `hongbia` (inverse-like `2→1`), `kongpia` (direct-like `1→2`), `kongkoih` (direct-like `1→2`).
2. **Compatible but not diagnostic:** `hongmu`, `kongmu`, `hongzui`.
3. **Deictic/venitive boundary:** `hongpai`, `hongbei`, and now `hongsawl` (demoted from supporting to boundary).
4. **Speech-formula/lexical boundary:** `kongci`, `konggenkik`, `hongsuahna`.
5. **Blocked literature constraints:** `hong-an-huan-sak`, `kong-bawl-sak`.
6. **Glossing convention for this packet:**
   - use `1→2` for clear kong direct-like rows;
   - use `2→1` for clear paired inverse-like hong rows;
   - use `SAP.ORIENT` for mixed quoted-speech hong rows such as Matthew 25:37;
   - use `VEN` for deictic/venitive motion rows.
7. **Cross-file harmonization required and implemented:**
   - candidate layer now records explicit person-configuration decisions (`person_configuration_decision`);
   - Matthew 25:37 glossing is harmonized between `grammar_hong_kong_object_prefix_print_slice.md` and `grammar_prefix_agreement_print_slice.md`;
   - speech-formula `kong` rows are kept separate from direct-like diagnostics.
