# Why there is no dictionary slice

There is no dictionary slice because this packet is constructional/morphological rather than lexical. It should not create dictionary entries for `bawlna`, `bawlpa`, `hong pai mi`, `omna`, or `muhna-ah`.

That restraint is especially important because `-pa`, `-mi`, lexicalized `-pa` forms, nominalized relatives, and nominalization-plus-case rows remain unsettled. The current packet is about a narrow `-na` nominalization claim, not about exporting a stable lexical headword layer from mixed morphological and constructional evidence.

# What does not yet work

This packet does not provide a full nominalization chapter. It does not provide a full derivation chapter. It does not provide a full relative-clause chapter. It does not provide a full case-routing chapter. It does not provide a full agentive `-pa` / `-mi` treatment. It does not provide a full nominalized-relative account.

It also does not yet provide a settled editorial split between productive agentive nominalization and lexicalized title-like nouns, nor a settled account of how person-head nominalization should be separated from relative-clause and prefix/agreement material. That restraint is useful. The packet works because it keeps the first claim smaller than the unresolved architecture around it.

# Boundary and deferred material

The packet’s deferred and boundary-only rows are now explicit.

- `bawlpa` remains outside the first core slice because agentive `-pa` still has to be separated from lexicalized and title-like rows.
- `hong pai mi` remains outside the first core slice because person-head `-mi` still overlaps with relative-clause analysis.
- `omna` remains outside the first core slice because nominalized relatives remain shared with clause linkage.
- `muhna-ah` remains outside the first core slice because nominalization plus case routing remains shared with case marking.
- `kumpipa` and `Topa` remain outside the first core slice because lexicalized or title-like `-pa` rows should not be mistaken for the cleanest productive anchor.
- `a bawl mi` and similar human-head relative rows remain outside the first core slice because they sit between nominalization, relative clauses, and prefix/agreement questions.
- bare `na` remains outside the first core slice because it is analyzer-noisy as a surface form.
- report-only counts remain outside the first core slice because attestation alone does not make a row safe for the first print-facing claim.
- any broad nominalization, derivation, relative-clause, or case-routing chapter claim remains outside the first core slice because the current packet is only a narrow `-na` slice.

These deferrals are also why the current packet should stop here. It is better to hand off a narrow stable `-na` nominalization slice than to force the broader nominalization system into premature print prose.
